## 1. 背景

OpenAI 于 2026 年 5 月为 Codex 桌面端（现并入 ChatGPT 桌面应用）上线了官方桌宠功能 **Pets**：像素风动画伙伴悬浮在屏幕上，用 Running / Needs input / Ready / Blocked 四种状态反映编程任务进度，社区已形成活跃的自定义宠物生态（Petdex、codexpet.top 等）。

ZCode 客户端本身没有、也无法被注入此类 UI 功能。但 ZCode 提供了完整的 **hooks 机制**（7 个会话事件），使得**独立桌宠应用 + hooks 状态联动**成为可行路径。

## 2. 目标用户

ZCode 的个人用户（首要用户为项目作者本人）；对桌宠/像素文化感兴趣的 AI 编程工具使用者。

## 3. 用户故事

- US-1：作为用户，我希望屏幕上有一只像素宠物，让我在切去别的应用时也能感知 ZCode 的任务进度。
- US-2：作为用户，我希望任务需要我批准或回答时，宠物能明显变化，让我第一时间回来处理。
- US-3：作为用户，我希望点击宠物就能跳回 ZCode/终端窗口。
- US-4：作为用户，我希望同时跑多个会话时，每个会话有一只宠物，互不混淆。
- US-5：作为用户，我希望能换宠物皮肤，最好能直接用 Codex 社区分享的宠物。
- US-6：作为用户，我希望长时间没有任务时宠物自动睡觉，不打扰我。

## 4. 功能需求

| 编号 | 需求 | 优先级 |
|---|---|---|
| F1 | 悬浮宠物窗：透明背景、无边框、always-on-top、可拖拽、位置持久化 | P0 |
| F2 | 像素动画引擎：Canvas 播放精灵表帧动画，支持 6 种状态动画 | P0 |
| F3 | ZCode 状态联动：通过 hooks 将 7 个会话事件映射为宠物状态 | P0 |
| F4 | 点击跳回：点击宠物通过 AppleScript 激活目标应用（ZCode → iTerm2 → Terminal，列表可配） | P0 |
| F5 | 多会话多宠物：每个活跃会话一只宠物窗（上限 5），自动排列，会话消亡自动回收 | P1 |
| F6 | 内置宠物 5 只（机器人/柴犬/鸭子/史莱姆/石头）+ 自定义宠物目录加载 | P1 |
| F7 | Codex 宠物格式兼容：加载符合社区规范的 pet.json + 1536×1872 精灵表 | P1 |
| F8 | 托盘菜单：切换宠物、唤醒/收起、退出 | P1 |
| F9 | 睡眠态：10 分钟无事件自动进入睡眠动画 | P2 |

## 5. 非功能需求

- N1 **性能**：hook 脚本执行 < 10ms（ZCode hooks 内联执行，不得拖慢会话）；桌宠空闲 CPU 占用 < 2%。
- N2 **稳定性**：ZCode 异常退出（无 Stop 事件）时，宠物状态可自愈（失联判定与回收）。
- N3 **兼容性**：macOS（Apple Silicon 优先验证）；精灵表兼容 Codex 社区 1536×1872 格式。
- N4 **隐私**：状态文件仅存本地 `~/.zcode-pet/`，不包含 prompt 内容、代码内容等敏感信息。

## 6. 非目标（本次明确不做）

- 窗口跟随（宠物不追踪 ZCode 窗口位置）
- AI 图像生成"孵化"宠物（开发环境无图像生成工具，用代码手绘替代）
- Windows / Linux 适配（架构保留可移植性）
- 养成/升级/喂食系统

## 7. 成功指标

- 四态联动 e2e 验收通过（真实 ZCode 会话驱动）
- 成功加载至少 1 只第三方社区宠物
- 桌宠空闲 CPU < 2%
